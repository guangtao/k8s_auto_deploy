# K8s 离线部署包 v3.1.0 发布说明

- 发布日期：2026-11-06
- 上一版本：无（首个按版本号发布的包；之前的包按 K8s 版本命名，如 `k8s-deploy-v1.33.4-amd64-20261013.tar.xz`）
- 部署包：`k8s-deploy-v3.1.0-amd64.tar.xz`、`k8s-deploy-v3.1.0-arm64.tar.xz`

## 本版变化

### 新增
- 部署包改用自己的版本号（`VERSION`），包名 `k8s-deploy-v<版本>-<架构>.tar.xz`；K8s 等组件版本写在包内 `RELEASE.md`、`BUNDLE_INFO.txt`。
- 出包后自动上传 OSS（`oss://cyberdownland/k8s_install/`），并打印下载地址和 SHA256。
- 部署机重启后自动续跑 `install`（一次性 systemd 服务 `k8s-deploy-resume`）。
- 可选步骤 04b：部署 Harbor（x86 2.10.2 / ARM 2.10.1）或 registry:2。
- 配置项 `kubernetes.dns_upstream`：离线内网节点没有 nameserver 时使用。

### 变更
- `kernel.upgrade` 默认开启：CentOS 7 x86 节点自动升级到 kernel-lt 5.4（K8s v1.33 要求内核 ≥ 4.15）。
- 02 步主动关闭防火墙（firewalld / ufw / iptables / nftables）、swap（含 systemd swap 单元、zram）、SELinux，麒麟 KYSEC 设为 softmode；precheck 对这些项改为 WARN。
- `harbor.node` 可直接填 IP。

### 修复
- 离线内网节点 `/etc/resolv.conf` 无 nameserver 导致 CoreDNS 起不来：02 步自动写入（留空用节点自身 IP 占位）。
- CentOS 7（python 3.6）装不上 jinja2：代码自带 Jinja2 3.0.3，无需安装。
- kk、kubeadm 等二进制经 Windows 中转后丢失可执行位，被误报"缺少"。
- 安装失败后重跑，etcd 因残留数据和 `/etc/etcd.env` 以 existing 状态启动、反复退出。
- 节点关机慢时被误判为已重启完成（改为按 boot_id 判断）。
- 同时运行两个出包进程互相破坏，打出截断的包。

## 升级说明

- 未部署完的现场：下载新包，把旧目录的 `scripts/render_config.py` 拷到新包覆盖，执行 `bash deploy.sh render`，再 `bash deploy.sh install -y`。
- 已部署好的集群：无需操作。

配置变化：新增 `kubernetes.dns_upstream`（默认空）；`kernel.upgrade` 默认值改为 True。旧配置文件不加新项也能用。

## 注意事项
- 下载后先校验 SHA256（`sha256sum -c k8s-deploy-v3.1.0-<架构>.sha256`），不一致不要解压。
- 麒麟 KYSEC 的处理第一次在麒麟上部署时请确认：02 步输出"麒麟 KYSEC 已设为 softmode"，`getstatus` 显示 softmode。
